Two skills, one boundary

Development chores live in one skill. Store submission lives in the other. Install both or just the one you need.

mobile-automation

The setup work that eats afternoons

Inspects your app's shape — framework, bundle ID, provider config — then automates what a CLI can do reliably.

  • Screenshots & demo videos — Maestro-first capture with fastlane and native CLI fallbacks
  • Auth plumbing — Sign in with Apple, Google Sign-In, Firebase Auth setup checks
  • Links — Universal Links and Android App Links validation
  • Push — APNs, FCM, and Expo/EAS credential setup checks
  • Console gaps — exact human guidance when only a dashboard will do
mobile-submission

Discovery to “Submitted for review”

Orchestrates the whole release: a machine-readable packet holds the state, a ledger records every decision, and you can resume any run.

  • Readiness review — Apple and Google preflight against a policy matrix
  • Rejection-risk gates — taxonomy of common rejections, checked before submit
  • Store execution — App Store Connect and Google Play via CLI/API
  • Dry-run by default — nothing is submitted without explicit intent
  • Growth pass — optional ASO, store conversion, and paid acquisition review

Install

Skill managers

Add both skills from the repo, or install one at a time.

npx skills add hhushhas/mobile-skills

# or one skill at a time
gh skill install hhushhas/mobile-skills mobile-submission
gh skill install hhushhas/mobile-skills mobile-automation

ZIP upload — ChatGPT & Claude

Both skill folders zip cleanly for the ChatGPT Skills page and Claude's skill upload. Build them from a checkout:

git clone https://github.com/hhushhas/mobile-skills
cd mobile-skills && ./scripts/package.sh
# → dist/mobile-submission.zip, dist/mobile-automation.zip

Built to not wreck your store account

  • Dry-run by default — store submission requires explicit submit intent.
  • Writes are announced — provider account changes are called out before execution.
  • Secrets stay secrets — referenced via env: / op:// style refs, never pasted.
  • Humans click dashboards — guided console tasks instead of browser automation.
