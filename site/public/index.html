Two skills

Everything between “it builds” and “it’s live”

mobile-submission

Repo to review to release.

  • Judges your app like a reviewer — against the current App Review Guidelines and Play policy pages, on your app’s real risk surfaces, before you waste a review cycle.
  • Ships the release — reads the diff, bumps versions everywhere (yes, CFBundleVersion and versionCode), writes release notes from what actually changed, builds, uploads, submits.
  • Handles rejections precisely — fetches the cited guideline, checks community experience, and knows when a resolution-center reply beats rebuilding.

mobile-screenshots

Listing media with no physical device.

  • Captures at accepted sizes — picks a simulator or emulator that already matches a store dimension, so nothing gets resized or rejected.
  • Validates before upload — Apple’s exact pixel pairs and Google’s aspect and alpha rules are machine-checkable, so they get checked locally.
  • Knows why art isn’t showing — icon-in-binary rules, Play’s review delay, managed publishing — checked before anyone suspects a caching bug.

How they’re built

Lean skills, honest state

CLI-first

Store work runs through asc and gplay. Browser automation is the fallback for web-only console forms, not the default.

The store is the source of truth

No packets, ledgers, or state files. The skill fetches live status from App Store Connect and Play Console and trusts that over anything written down earlier.

Humans do only owner steps

You’re handed exactly the actions an account owner must personally take — agreements, first-time enrollments, final approvals — and nothing else.

Install

In your agent in under a minute

With the skills CLI (any Agent Skills–compatible agent):

$npx skills add hhushhas/mobile-skills

Or with the GitHub CLI:

$gh skill install hhushhas/mobile-skills mobile-submission

Or copy either skill folder into your agent’s skills directory and invoke it — mobile-submission and mobile-screenshots are plain SKILL.md folders, MIT-licensed.
